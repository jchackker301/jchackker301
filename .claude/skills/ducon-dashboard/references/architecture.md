# Architecture: how the War Room is built

Read this before changing code. The rules at the bottom must not break.

## Files (under the site folder, `site/` in the bundle)
- `public/index.html`: the whole page. One file: CSS, HTML, one IIFE for the data layer, and the main script.
- `functions/api/[[path]].js`: the API (Cloudflare Pages Functions). Routes, validation, sign-in.
- `functions/lib/skill.js`: GENERATED by `tools/sync-skill.mjs`. Holds the bundle (skill files + site source). Do not edit by hand.
- `tools/sync-skill.mjs`: builds the bundle. Has a secret guard.
- `tools/pull-source.mjs`: downloads the deployed bundle into a folder.
- `tools/pull-live.mjs`: copies live records into the local test database.
- `tools/desk.mjs`: agent CLI (`all`, `skills`, `put`, `del`).
- `schema.sql`: one table, `records (table_name, id, data, updated_by, updated_at)`, primary key (table_name, id).
- `wrangler.toml`: Pages project and the D1 binding `DB`.
- `package.json`: scripts `dev`, `db:local`, `db:remote`, `skill:sync`, `deploy`.

## Data model (stored as JSON in `records.data`)
- **videos** (id free text): `title`, `tier` A|B|C, `kind` project|other, `status` idea|theme|ready|prod|done, `assignee` Jayson|Alex|'', `owner`, `editor`, `postDate`, `editDeadline`, `slotDate`, `deliveredAt`, `readyAt` (dates YYYY-MM-DD), `theme`, `brief`, `desc`, `revisions`, `wildcard`, `swap`, `manual`, `gate`, `appr`, `source` (for example `ops-chat`).
- **events** (missions and recurring): `title`, `type`, `place`, `notes`, `eta` (YYYY-MM-DDTHH:MM), `who` Both|Jayson|Alex, `value` High|Medium|Low, `done`, `recurring`, `next` (YYYY-MM-DD), `exact`.
- **projects** (long-standing, no dates): `title` (required), `who` Both|Jayson|Alex, `status` ongoing|paused|done, `notes`, `updates` [{`d` YYYY-MM-DD, `t` text, `k` video|task (missing = task), `by` 'Team'}], `createdAt`, `doneAt`. Returned by `/api/all` as `projects`.
- **intel** (id = YYYY-MM, written by Claude after a WhatsApp scan): `headline`, `scannedAt`, `source`, `clues` [{t,d,who}], `tips` [{t,why,basis}], `links` [{d,who,kind,title,path,fed}], `unconfirmed` [{d,t}]. Page code: Intel module before the work report section (renderBrief, briefTip, linkFed), Home INTEL lines in renderIntel.
- **shoots** (client photo/video shoots): `client` (required), `date` YYYY-MM-DD (required), `kind` backyard|showroom|event, `media` photo|video|both, `who` Both|Jayson|Alex, `place`, `folder` (<=500), `notes` (<=1000), `fromEvent` (mission id). Counted in LVL and month totals; index.html code: shoots module before the work report section, Squad card 05 via shootCardHTML.
- **settings** (id `team`): `editors`, `hours`, `buffer`, `weekOv` (manual slot overrides keyed `<monday>|<person>|<dayIdx>` with value done|open).
- **skills** (id = skill name, lowercase, 2 to 60 characters): `text` (SKILL.md content, required), `description` (optional, up to 300 characters). `ducon-dashboard` is reserved.

Validation lives in `badField(table, data, id)` in the API. The page and the API must agree on these rules.

## API (`/api/...`)
- Human callers: a personal code sent as `Authorization: Bearer <code>` (secrets `KEY_JAYSON`, `KEY_ALEX`), or Cloudflare Access JWT when `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` are set. Localhost is signed in as `local@localhost`.
- Agent callers: `/api/agent/...` with `Authorization: Bearer <AGENT_API_KEY>` (secret). Without the secret set, agent access is off.
- Routes: `GET me`, `GET all` (videos, events, settings; never skills), `GET skill` (bundle: text + files), `GET skills` (custom skills with text), `PUT record/<table>/<id>` (validated upsert), `DELETE record/<table>/<id>`.
- Body limits: 60 KB for most tables, 200 KB for skills.

## Page structure (public/index.html)
- Rooms: `data-room` on sections; `showRoom(r)` switches them and remembers the room (hash + localStorage `deskRoom`). Rooms: home, cal, inv, board, proj, focus, rep, skills.
- Renderers: `renderScore` (operator rows), `renderSide` (Mission, Daily Challenges, recurring promo), `renderHero` (ring and stats), `renderRail` (LVL, badges), `renderIntel` (INTEL strip), `renderGodView`, `renderCalendar`, `renderBoard`, `renderInventory`, `renderFocus` (missions), `renderReport`, `renderSkills`. `renderAll()` calls them under `keepFocus`.
- Shared helpers: `slotInfo` / `slotShown` / `slotState` (daily slots and manual overrides), `refDate`, `isOverdue`, `squadWeek`, `foldList` (fold after N, remembers open state), `mondayOf`, `addDays`, `parse`, `iso`, `short`, `evEta`, `evLeft`, `zipStore` + `crc32` (zip writer, used by .zip and .xlsx), `buildXlsx`.
- Data layer: an IIFE with `run(fn, args)` that calls `/api`. It is exposed as `window.claude.use('db')`, `window.deskSkill`, `window.deskSkills`, `window.deskSkillSave`, `window.deskSkillDelete`. Polling every 20 seconds refreshes the data.
- Skills room: `skillState`, `renderSkills`, `loadSkill`, `skillLoadCustom`, `skillAct` (every `data-act` starting with `skill`), `skillSave`, `skillRemove`, `skillZipFile`.

## Invariants (must not break)
1. One week is Monday to Sunday and it follows the week arrows everywhere.
2. Daily slots: Mon B, Tue C, Wed B, Thu C, Fri B, Sat A, per person. Plus 2 client project videos a week. A manual override (`weekOv`) beats the automatic result.
3. Overdue = not done and (editDeadline or postDate) before today. Same rule in every room.
4. Counting: an approved finished video counts once. Removed records disappear from every count.
5. The Team room stays removed. No red/blue person colours. Names are plain.
6. Compact: Home fits one screen at 1440x900, every room about 1 to 1.15 screens.
7. The skill bundle contains no secrets. `sync-skill.mjs` must keep its guard.
8. `/api/all` never returns skill text. The 20-second poll stays light.
